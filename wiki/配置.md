# 配置

[English](Configuration) | **简体中文**

插件没有 profile `cordis.patch.yml` 配置字段，全部数据都在插件自己的本地状态中。

## 存储位置

| 内容 | 位置 |
| --- | --- |
| 工作区默认值 | `$DSH_HOME/storages/workspace-settings/settings.json` |
| Chat 展示偏好基线 | 浏览器 `localStorage`，键 `dsh-workspace-settings:chat-baseline:v1` |
| 每个会话的“上次应用”缓存 | 同一 `settings.json` 的 `sessions` 段（派生数据，可安全丢失） |

`$DSH_HOME` 默认是 `~/.dsh`（Windows 为 `C:\Users\<用户>\.dsh`）。第一次保存修改时创建
JSON 文件；删除该文件会清空所有工作区默认值。

## 跟随全局 vs. 覆盖

每个字段都有显式的“跟随全局默认”取值。选择它会从存储记录中移除该覆盖；六项全部跟随全局时，
整个工作区记录会被删除。

全局值本身仍由 DSH 官方设置持有：

- 模式默认：设置 → Agent 预设 / 新会话预设选择器。
- 权限默认：设置 → 通用设置 → 权限。
- 模型默认：模型选择器 / 模型设置。
- 工作步骤展示与收起时机：设置 → 通用设置。

## 工作区键

记录以工作区的规范化路径为键，而不是显示标题或工作区 id。因此：

- 重命名工作区不会丢失设置；
- 把工作区移到别的目录会生成新记录，旧记录保留在旧路径下，直到手动删除；
- 两个指向同一路径的工作区条目共享同一条记录。

匹配新会话 `cwd` 前会做路径规范化（分隔符、末尾斜杠不敏感，Windows 下大小写不敏感）。

## 手动编辑

插件停止时可以直接编辑 JSON：

```json
{
  "version": 1,
  "workspaces": {
    "c:/projects/demo": {
      "path": "C:\\Projects\\demo",
      "workspaceId": "workspace-...",
      "preset": "creative",
      "permission": "workspace-write",
      "model": { "provider": "deepseek-official", "model": "deepseek-flash", "reasoningEffort": "max" },
      "transcriptView": "standard",
      "collapseTiming": "completion",
      "updatedAt": "2026-10-27T00:00:00.000Z"
    }
  },
  "sessions": {}
}
```

加载时非法记录会被丢弃；当前 catalog 中不存在的预设 / 权限 / 模型会在编辑器里被掩码为
“跟随全局”，直到它们重新可用。

## Chat 展示偏好基线

工作步骤展示与收起时机是官方全局 Chat 偏好。插件首次应用工作区覆盖前，会把当时生效的值
记录到上面的 `localStorage` 键。清除该键即可重置插件保存的基线。完整切换规则见
[架构](架构#chat-展示偏好-watcher)。

## 多 profile

存储跟随 `$DSH_HOME`，所以不同 DSH home / profile 的工作区设置互相独立；浏览器基线按
browser origin/profile 保存在 `localStorage`。

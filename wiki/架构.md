# 架构

[English](Architecture) | **简体中文**

插件由一个 bundle 的宿主端、客户端与 Loader patch 组成。

## 宿主端 — `index.js`

注入 `webServer`（可选 `connection`），其他能力通过 `ctx.get()` 惰性读取，缺少服务的组合中
插件保持不生效：

- `workspaceRegistry` — 工作区 id、标题与规范化路径。
- `agentPresets` — 预设名册与 `select(agent, id)`（仅空白会话）。
- `permissionPresets` — 预设目录、当前生效预设与 `set(session, name)`。
- `sessionController.modelCatalog()` — 可路由模型与推理强度。
- `agentDefaultModel.currentSelection()` — 全局默认模型。
- `sessionProjections` — `turnBoundary`、`agentPreset`、`modelSelection` 状态。
- `agents` — 启动时与保存后对空白会话补应用。

### 路由

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/workspace-settings/catalog` | 工作区、实时预设/权限/模型、全局默认、已存值 |
| `POST` | `/api/workspace-settings/save` | 校验并保存一个工作区文档；返回刷新后的 catalog 与更新了多少空白会话 |

有 `ctx.connection.fetch` 时注册在认证浏览器通道；否则使用 `ctx.webServer` 前缀路由，并做
同源 / Host 校验。请求体上限 256 KiB，错误带稳定的 `{ code, message }`。

### 会话创建时的继承

`agent/created` 是串行且可等待事件，因此默认值会在新 Agent 可被 prompt 使用前应用。插件：

1. 跳过子代理、分叉与已经开始对话的会话；
2. 用 Session header 的 `cwd` 查工作区记录；
3. 仅在会话空白时用 `agentPresets.select()` 应用模式；
4. 用 `permissionPresets.set()` 应用权限（写入正常 Session 事件）；
5. 存了模型时安装首请求覆盖；
6. 把生效的预设/权限写入每个会话的小缓存。

该缓存用来区分“仍是全局默认 / 插件上次应用的值”和“用户在会话内改过”；只有前两种会在下次
复用同一空白会话时被替换。缓存是派生数据，可丢失。

### 模型覆盖

模型不会写入全局默认。插件在 Agent 作用域注册 `system-prompt/assemble` 与 `agent/request`
监听器（`{ prepend: true }`），仅在以下条件同时成立时覆盖 provider/model/effort：

- 会话还没有 request header（首个请求）；
- `modelSelection` 投影没有待应用的显式选择。

request header 记录后监听器不再修改，后续请求由会话自己的模型选择器决定。

### Chat 展示偏好 watcher

工作步骤展示 / 收起时机是全局 `ui-chat` 偏好。客户端 watcher：

1. 读取并订阅 `ctx.configForms.get('ui-chat')`；
2. 从 `ctx.sessions.list` 找当前激活会话（`retainedBy.mainView > 0`）；
3. 通过共享 catalog 找到其工作区；
4. 把这两个官方偏好字段切换到工作区值；工作区没有覆盖或会话不属于工作区时切回捕获的全局
   基线；
5. 非 watcher 写入的变化会被当作新基线（这样手动修改的全局值会成为离开时恢复的值）。

这两项不写任何 Session 事件。

## 客户端 — `client.js`

注册：

- `settings.section` — **工作区设置** 页面（id `workspace-settings`，order 25）。
- `shell.overlay` — 识别 `data-row-key="workspace:<id>"` 工作区行，接管 `...` 按钮与右键，
  用官方 `Menu` 渲染完整菜单；重命名/删除调用公开的 `ctx.workspaces` 服务。
- 本地 `<style>` 与词典；控件全部使用宿主原语（`Menu`、`Modal`、`Button`、`Input`）与主题
  token。对话框行/选择器复制宿主权限设置行的几何，因此深浅色主题都跟随官方外观。

DSH 0.2.1 没有工作区菜单项的扩展槽位，所以需要浮层接管。未来宿主若提供原生槽位，客户端应
改为在槽位里注册菜单项。

## Loader patch

`cordis.patch.yml` 以空 config 插入 `workspace-settings` 宿主行；客户端清单在
`package.json` 的 `dsh.client` 中。

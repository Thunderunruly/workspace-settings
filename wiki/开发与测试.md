# 开发与测试

[English](Development) | **简体中文**

## 目录

```
client.js           # 客户端：设置页、工作区菜单浮层、Chat 偏好 watcher
index.js            # 宿主端：JSON 存储、Web 路由、会话继承
cordis.patch.yml    # 插入 workspace-settings 宿主行的 bundle patch
package.json        # bundle 清单（dsh.bundle / dsh.client、locale/icon 导出）
locale/             # 插件标题/描述词典（中文、英文）
icon.svg            # 插件图标
test/host.check.mjs # 离线宿主检查（node:test）
wiki/               # GitHub Wiki 页面源文件（DSH 不会加载）
```

## 离线检查

无需浏览器或运行中的 DSH：

```powershell
node --check index.js
node --check client.js
node --test test/host.check.mjs
```

`test/host.check.mjs` 用小型 fake 替代 Cordis 服务与 web server，覆盖：

- 路径规范化和存储记录规范化；
- 按实时预设/权限/模型 catalog 校验请求；
- catalog/save 路由与 JSON 存储；
- `agent/created` 时的预设与权限继承；
- 首请求模型覆盖及其强度合并逻辑。

项目没有构建步骤：`client.js` 是手写单文件模块 bundle；React 与 UI 原语从运行中的宿主
模块表获取，`package.json` 的 `dsh.client.external` 声明了
`@deepseek-ai/dsh-client-ui-primitives`。

## 本地迭代

1. 以 linked bundle 方式安装本目录（见 [安装](安装)）。
2. 修改客户端文件；首次安装后重载 DSH 窗口。
3. 宿主端改动需要禁用/重新启用插件行（或重启窗口）。
4. 用 Cordis 检查工具确认实时槽位：
   - `cordis_inspect_query` 客户端 `Slots.listSubTree` 根 `settings.section` 应出现
     `workspace-settings`；
   - 根 `shell.overlay` 应出现 `workspace-settings-overlay`。
5. 浏览器控制台中的插件日志以 `[workspace-settings]` 开头。

## 设计约定

- 使用宿主官方原语（`Menu`、`Modal`、`Button`、`Input`）与 `--dsw-alias-*` 主题 token；
  不复制应用外壳、不另起一套 chrome。
- 行/选择器几何与官方权限设置行保持一致；调整样式时保持这一点。
- 新 UI 文案走客户端词典（`NS = 'workspace-settings'`），插件元数据走
  `locale/zh.json` / `locale/en.json`。
- 存储字段保持可空、可追加；若改结构需提升 `version` 并加入归一化迁移。

## 发布流程

1. 更新 `package.json` 的 `version`。
2. 行为变化时更新 [版本记录](版本记录) 与 README 功能列表。
3. 提交并打 tag：`git tag v1.0.0 && git push --tags`。
4. 在 GitHub 用该 tag 创建 Release，说明与版本记录一致。
5. npm 发布是可选项，目前尚未发布。若发布无需移除任何东西：包没有运行时依赖，可作为普通
   DSH 插件 bundle 安装。

兼容目标：DSH `0.2.1-rc.3`；manifest 声明
`engines.dsh = ">=0.2.1-rc.3 <0.3.0-0"`。
